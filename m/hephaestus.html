Hephaestus — Operator Manual

CAM module of the Livyatan Design Suite. Boundary or STL in, G-code out. Local-first, no network, no web tech. PolyForm Small Business license.

The window

hephaestus-win — the CAM floor, seen. Load a boundary JSON; the stock appears as a block on the graph-paper table with the boundary traced on top. Stack ops from the left rail (Profile / Pocket / Rough / Drill — each runs the proven CLI engine with the current Tool/Depth), and every op's toolpath lands on the stock color-coded (per-op cut color, grey rapids). The right panel lists ops — click one to toggle it on/off (paths hide, sim and export skip it).

STL lane: Load STL… puts the part itself in the scene, ghosted amber inside the generated stock. The orientation grid (Z/X/Y down/up) works like a slicer's orient chooser — each candidate is scored by stock volume × undercut fraction, and AUTO orient picks the winner (the status line shows all six scores). The STOCK line is the stock generator: exact piece dimensions for the active setup, side margins included.

Setups: each setup = one orientation + its own op stack (the right panel). + Setup adds one; click a setup to switch. Export writes the ACTIVE setup's file — one .nc per setup, because that's the real machine day: cut, unclamp, flip, re-indicate, run the next file. v1 sims each setup from virgin stock; carried-over voxel stock across flips is queued v2.

3D ops: + Rough 3D (z-level waterline) and + Surface (raster finish) run the engine's STL heightmap lane against the active setup's orientation; the Depth/pass dial is the pass depth for 3D ops.

Drill by pointing: arm Drill: click stock, click the stock top — each click plants a red marker (click a marker again to remove it); Drill: fine-tune… opens the point list as editable numbers (X Y per line, mm) for exact placement; Drill -> op turns the points into a real peck-drill op. No holes.json needed (Load boundary… never asked for one — drill is its own point list, now built by clicking).

Stock opacity slider (under the STOCK line): solid at the right, ghost in the middle, and at the far-left stop the stock collapses to a wireframe of its 12 edges — the part and paths stand clear.

Paths: on/off hides every toolpath overlay at once (per-op toggles still work in the right panel) — useful when 3D rasters bury the part. Navigation (top-center row, same placement as Ouranos) opens the NAV pane: mouse orbit/zoom/pan sensitivity and direction plus SpaceMouse sens/speed — tuned here, saved to Hephaestus's own navigation settings. The puck itself works live: twist yaws, tilt flies/strafes, push/pull lifts, Shift = attitude.

Stock sim: SIM: run carves the height-field stock with the enabled ops' cut moves, live, ~40 segments a frame — orbit the piece while it runs (RMB drag = orbit, wheel = zoom, MMB = pan). SIM: reset restores virgin stock. EXPORT writes the enabled ops in order, op-headers included.

Boundary sources (no hand-written JSON needed): Stock block (W D H)… types a blank's dimensions — the boundary becomes its outline and H drives the stock thickness. Boundary from STL derives the outline from the loaded part: its XY footprint hull in the active setup's orientation (2D ops then cut at the stock top — where the machine gets zeroed anyway). Load boundary… still takes an explicit boundary.json from Glyptica/Structor.

Sim concept: Kiri:Moto anim-2d (MIT), reimplemented as a Rust height-field.

Quickstart

# Profile: cut a 40×25 plate free, 4 hold-down tabs, 3° ramp entry
echo '{"boundary":[[0,0],[40,0],[40,25],[0,25]]}' > part.json
hephaestus profile part.json -o part.nc \
    --tool 3.175 --depth 6 --pass 2 --ramp 3 --tabs 4 --tab-height 1.2

# Pocket: clear inside, leave a boss standing
hephaestus pocket part.json --islands boss.json -o pocket.nc \
    --tool 3 --depth 2 --stepover 1.5 --ramp 3

# Drill: peck cycle at each point (min 3 points — see Known limits)
echo '[[10,10],[30,10],[20,18]]' > holes.json
hephaestus drill holes.json -o drill.nc --depth 6 --pass 1.5

# Rough: clear stock down to a part shadow, 0.5 mm left on walls
hephaestus rough stock.json --part shadow.json -o rough.nc \
    --tool 6 --leave 0.5 --ramp 3 --stepover 3

# 3D from STL: surface finish + z-level rough (set --safe ABOVE the part top)
hephaestus surface dome.stl -o fin.nc --tool 3 --stepover 1.5 --res 0.75 --safe 20
hephaestus rough3d dome.stl -o r3.nc --tool 6 --pass 2 --stepover 3 --safe 20

With no args it prints usage and exits 2 — it never launches silent.

What it is

Two toolpath engines behind one CLI:

  • 2.5D router/plasma: profile with cutter comp + hold-down tabs, island-aware pocket clearing, stock roughing — all with ramp entry. Plus peck drilling, which straight-plunges by design.
  • 3D from STL: the part becomes a tool-compensated heightmap (flat-endmill drop-cutter), then surface-finish raster and z-level roughing scan it.

Methods lifted from Kiri:Moto's CAM (grid-apps src/kiri/mode/cam, MIT, © Stewart Allen) — ported to Rust on the Dido geometry seam, not transliterated.

Features

2.5D ops (input: boundary JSON):

  • profile — tool rides one radius OUTSIDE the boundary (Dido offset = the cutter comp), so the finished part measures the drawing. Optional hold-down tabs: --tabs N evenly spaced windows around the loop, each --tab-width wide, left standing --tab-height above the floor. Tabs mid-straight-edge are real (vertices are resampled at every tab boundary — the 2026-08-13 cut-through bug is fixed, with a regression test); the entry ramp also respects tab #0 at the loop start.
  • pocket — concentric inward offset rings per depth pass. --islands FILE keeps a region standing: island grown by tool radius, subtracted from every ring.
  • rough — stock clearing = pocketing the stock with the part shadow as the island, shadow pre-grown by --leave (default 0.5 mm on the walls).
  • drill — G83-style peck at each XY point: plunge one peck (--pass, floor 0.2 mm), FULL retract to safe Z to clear chips, repeat to depth. Straight plunge by design (a drill bit center-cuts). --ramp on drill is refused loudly with an explanation — helical entry for router-bit holes is queued, not silently faked.
  • Ramp entry (--ramp DEG, default 0 = straight plunge for plasma/drills): the tool rapids through air to just above the material, then descends the one-pass material step ALONG the loop. A loop too short to ramp at that angle falls back to a plunge (deliberate, commented in code).

3D ops (input: binary or ASCII STL, Z-up):

  • Mesh is welded, XY-centered, and rested with min-Z on the plate — G-code origin is the part's XY center, Z0 is the plate.
  • surface — boustrophedon raster following the compensated surface, rows --stepover apart.
  • rough3d — z-level raster from the top down by --pass; pen-up over standing part, cutting only where stock sits above level + --leave.
  • --res sets grid cell size (default tool/4, floor 0.25 mm); grids over 8M cells refuse loudly — raise --res.

Boundary JSON — the contract with the 2D design side: {"boundary": [[x,y], ...]} or a bare [[x,y], ...]. Millimeters. Same shape for --islands/--part files and for drill point lists.

G-code out: G21 G90 G94 preamble, M3 S<rpm>, G0/G1 moves only, M5/M2 close. Feeds and speeds are pass-through — you supply --feed --plunge --rpm (defaults: 3.175 mm tool, 600 mm/min feed, 200 plunge, 12000 RPM — 1/8" hobby-router numbers). No feeds/speeds calculator lives here; ask Oannes' advisor lane for numbers.

Using it

hephaestus <profile|pocket|rough|drill|surface|rough3d> <input> [-o out.nc] [flags]

No -o prints G-code to stdout. Flags (all optional, mm / mm-min / degrees):

flag ops meaning default
--tool all tool diameter 3.175
--depth 2D total cut depth (positive down) 3.0
--pass all per-pass Z step / drill peck / 3D level 1.0
--stepover pocket, rough, 3D radial / row step 1.5
--feed --plunge --rpm all cutting feeds, spindle 600 / 200 / 12000
--safe all retract Z — must clear the part on 3D ops 5.0
--ramp profile, pocket, rough entry ramp angle; refused on drill 0
--tabs --tab-width --tab-height profile hold-down bridges 0 / 6.0 / 1.0
--islands / --part pocket / rough second boundary JSON none
--leave rough, rough3d stock left on walls / surface 0.5
--res 3D heightmap cell size tool/4

Exit codes: 0 ok, 1 op error (message on stderr), 2 usage.

How it connects

  • Upstream: Structor (2D design) emits boundary JSON; Structor and GilgaMESH emit the STLs the 3D lane eats.
  • Dido does all 2D offsetting/subtraction — cutter comp, pocket rings, and island keep-outs are Dido calls.
  • Downstream: the .nc opens in Nazca, the toolpath viewer. Oannes' G-code post cleans the output (arc consolidation lives there).

Known limits

  • Drill needs ≥3 points — hole lists ride the boundary parser, which rejects fewer. One or two holes: fails loudly, pad the file or edit by hand.
  • --islands/--part reads ONE polygon, and drops it SILENTLY on a missing/bad file — a rough with a botched shadow path clears through your part. Eyeball the path in Nazca before cutting. The silent drop is an open issue.
  • --safe defaults to 5 mm — on 3D parts taller than that, rapids between raster rows would plow the part. Always pass --safe above the stock top.
  • The usage string omits surface/rough3d; both work.
  • No G2/G3 arcs — polyline output only; Dido's 1e-3 arc tolerance makes rounded corners verbose. Arc fitting queued (consolidation lives in Oannes).
  • Flat endmill only in the 3D heightmap comp; ballnose gouges are on you.
  • Raster 3D output is dense by nature; adaptive stepover would thin flats.
  • Small pocket rings that can't ramp at your angle plunge instead — by design, not announced per-ring.

Queued

  • Ballnose compensation for the heightmap.
  • Helical ramp entry for holes/features too small to linear-ramp.
  • G2/G3 arc fitting on output.
  • Adaptive stepover on 3D flats.
