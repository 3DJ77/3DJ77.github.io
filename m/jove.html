Quickstart

cd ~/XOS/Jove
cargo build --release --features prep
./target/release/jove-prep
  1. Load model… — zenity picker, STL only. Part lands XY-centered, rested on the plate.
  2. Orient with the X/Y/Z ±90° buttons. Rotating clears any placed holes/supports (narrated) — place marks after you orient.
  3. Auto: ON for Kiri island supports; Add/remove… arms picking for manual pillars (click part = add blue marker, click within 3 mm of one = remove).
  4. Drill drains… arms picking; each click stores a red drain at the current Hole r (1.0 / 1.5 / 2.0 mm).
  5. Pick Layer (0.025 / 0.05 / 0.1 mm), hit SLICE -> .ctb, point the save dialog anywhere — flash drives live under /media. Default lands in ~/Desktop/bezier/<part>.ctb.

Camera: right-drag orbits, wheel zooms (scroll up = camera away). Left click only picks when a mode is armed, and only right of the panel.

What it is

The hands of the resin lane. A fyrox window (jove-prep) for orient / drains / supports / slice, driving two headless stages: tools/jove_slice.py (trimesh sections, shapely polygons, PIL rasterizes — raw mask stack streamed to disk, never held in RAM) and the jove CLI (the ctb_writer crate, vendored from Open Resin Alliance's MIT df-plugin-ctb), which streams masks one layer at a time into a finished .ctb. Target machine: Elegoo Jupiter 6K — .ctb v5, 5448 x 3064, 51 um pixels, mirror X, 277.8 x 156.3 mm plate. The plate in the window is that plate, to the millimetre.

Features

  • Plate view — graph-paper Jupiter plate, dark slab, orbit camera; part in amber, drains red, manual supports blue.
  • ±90° rotates on print-space X/Y/Z; part re-rests on the plate after every turn. (Fine rotation not built.)
  • Auto supports — Kiri:Moto's SLA algorithm, ported MIT lift: island detection (layer minus grown layer-below), contact sampling (centroid + boundary every 6 mm), clustering, tapered pillars (tip → branch → trunk radii, Kiri's own constants), 3-foot flare bases with pads, on-model landings with a tip pad. Merge-routing (findMergeNode/maxTreeMove) is phase 2 — one pillar per contact for now.
  • Manual supports — click-to-add / click-near-to-remove picking; each point threads through --support-at X,Y,Z and becomes a pillar from that clicked surface point. Combines with auto.
  • Drain holes — vertical through-bores erased in mask space every layer (the UVtools way, no mesh CSG). Each hole keeps the radius it was placed at — cycling Hole r afterward does not retro-edit old holes.
  • Flare feet — legs lerp from flared-at-the-plate to the trunk hub going up, so foot pads bond to their legs. (The old lerp inverted this; fixed, comment in jove_support.py tells the story.)
  • Slice to .ctb — watertight-checked, plate-fit-checked mask stack, then the streaming Rust writer. --metadata JSON overrides exposure/lift; defaults are Jupiter starting values, not correct ones — run an exposure ladder.
  • Encrypted-ctb machinery — the vendored writer carries the CTB AES-256-CBC block cipher and per-layer XOR scrambling. The encoder currently passes XOR key 0 (v4-style, scrambling off).

Using it

The window never blocks: file dialogs and the slice job run on threads, progress lands in the status line (and echoes to stdout as JOVE …). One pick mode at a time — arming drills disarms supports and vice versa. Clear holes / Clear supports wipe their marks. SLICE writes a temp STL of the oriented part, runs jove_slice.py (prints SUPPORTS … counts and layer n/N progress), then target/release/jove writes the container and cleans up the temps. OK -> path or FAIL reason — no silent outcomes.

Headless use, no window needed:

python3 tools/jove_slice.py --stl part.stl --out masks.raw --layer-height 0.05 --supports
./target/release/jove --masks masks.raw --out part.ctb --layers N --layer-height 0.05

jove --print-metadata dumps the default exposure JSON to edit and feed back with --metadata. --no-mirror-x, --width/--height/--pixel-mm cover non-Jupiter machines.

Fail-loud, by design: non-watertight mesh dies with one line (repair first — GilgaMESH output is watertight); part bigger than the plate dies; an all-empty stack dies; a mask stack whose byte count disagrees with the layer grid is refused up front, because the alternative is a diagonally sheared print you only discover in the tank.

Panel reference

Button Does
Load model… zenity STL picker (async, window stays live)
X/Y/Z −90° / +90° rotate in print space, re-rest on plate, clear marks
Drill drains… arm/disarm drain picking (disarms support picking)
Hole r: N mm cycle 1.0 → 1.5 → 2.0; applies to holes placed after
Clear holes drop all drains
Auto: off/ON toggle Kiri auto supports at slice time
Add/remove… (n) arm/disarm manual support picking; n = count
Clear supports drop all manual points
Layer: N mm cycle 0.025 → 0.05 → 0.1
SLICE -> .ctb write temp STL, run the two stages, save dialog

How it connects

  • In: STL exports from Vitruvius, GilgaMESH, or Ouranos — anything that emits a watertight STL.
  • Out: .ctb for the Jupiter. Inspect it in Labyrinth (the viewer, ex-Daedalus) before committing resin — note Labyrinth's encrypted-ctb decode is a known open bug on its side.
  • Tiamat (the suite host window) probes for and launches jove-prep.
  • The ctb_writer lib is a clean crate boundary: any caller that can produce a raw mask stack and run a process can write a .ctb — that is the whole contract.

Known limits

  • The test suite does not compile. cargo test dies at src/ctb/shim.rs:109 — a stale crate::slicer::PixelGrid reference left from the scrapped Rust rasteriser (deep-review 2.4). Verified today: error[E0433] could not find slicer in the crate root, jove (lib test) fails to build. Consequence: the .ctb safety asserts in src/lib.rs — mask-size shear refusal, valid header magic, nonzero exposure, empty-input rejection — and the STL round-trip tests in jove-prep do not run. The runtime checks exist in the shipping code paths, but we are flying blind on regression coverage until the ref is fixed. tests/e2e.sh (annulus + floating-cube supports, real masks, real .ctb) is the runnable check meanwhile — needs the release binary and python deps.
  • Rotating the part clears all holes and supports; holes are plate-space, not surface-anchored, so they cannot ride the part through a re-orient yet.
  • Support merge-routing not built — dense contact fields mean dense pillar forests.
  • Metadata defaults are starting values; real exposure numbers come off your machine, your resin, your room.
