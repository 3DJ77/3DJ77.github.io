Iris — Operator Manual

Laser & plasma prep module of the Leviathan Design Suite. Sovereign, local-first, PolyForm Small Business licensed. Image or SVG in, Longer Ray5 G-code out.

Quickstart

cd ~/XOS/Iris
cargo run --release --features prep --bin iris-prep
  1. Drop an image (PNG/JPG/BMP) or SVG onto the window — or click Load art….
  2. Drag the art where it burns. Corner/edge handles resize; type exact W/H and press Enter. Unit cycles mm / in / px (px = source-image pixels).
  3. Set Mode (engrave / outline), Dither, Power (20–100%), Kerf (0 → 0.3 mm in 0.1 steps), Process (laser / plasma).
  4. GENERATE -> .nc — pick the save path (defaults to ~/Desktop/bezier/<stem>.nc). The cut path draws on the bed when done: amber = cut, grey = travel, red cross = plasma pierce.

CLI, no window: ./iris --in art.png --out job.nc --mode dithering (bare ./iris runs a zenity pick-input/pick-output flow). Chat CLI: ./iris-chat "engrave logo.svg at 120mm, svg, kerf 0.1".

What it is

Iris is the flat-cut lane: everything that burns or pierces sheet stock. One prep window (src/bin/iris-prep.rs, fyrox, locked top-down 2D), one cut engine. Raster engraving runs on the Rust engine (src/engine.rs); vector, SVG, and plasma run on the Python engine (tools/iris_cut_engine.py, the escher engine lifted from LaserChat). The window is the hands; the engines do the work over their CLIs. Chat prep (tools/iris_chat.py) turns plain English into engine parameters via the LLM resident on Tia.

Why the name

Iris: the rainbow goddess, messenger of the gods — a beam of light carrying the message. Here the light IS the message and the cutter both: the module whose entire job is steering a beam across a flat bed.

Features

  • Unified prep window — drop art, chat, toggle settings, place and size on a 2D top-down bed preview (the Nazca bed concept: graph-paper grid, 25 mm minor / 100 mm major lines, 850×850 mm = Ray5 + XY extension kit).
  • Direct manipulation — drag to move, 8 resize handles, aspect lock, Mirror / Flip (baked into pixels), undo Ctrl+Z / redo Ctrl+X, middle-drag pan, wheel zoom.
  • Rust raster engine (landed 2026-08-14) — raster engrave lane. Halftones: floyd, atkinson, burkes, jarvis, stucki (window set); plus threshold, bayer4x4, and straight grayscale power modulation in the library. Run-length G-code emission (G0 across blanks, one G1 per constant-power run). Lifted from gcodekit4 (MIT) with three machine-safety fixes: inverted power mapping, laser-on travel across blank gaps, and a $H/G10/Z prolog that doesn't belong in a Ray5 job file.
  • Python engine modes — line2line (grayscale modulation), dithering (9 algorithms), vectorize (potrace outline of a raster), centerline (skimage skeleton), svg (vector input). Scan directions: horizontal, vertical, diagonal, rdiagonal, grid, dgrid, cross, dcross, zigzag, hilbert.
  • Kerf compensation — closed vector paths offset outward by kerf/2 so the burned edge lands on the drawn line. Engine refuses kerf on raster modes loudly (fail-loud, not silently dropped).
  • Plasma lane — cut-only (torch can't shade). M3/M5 torch control, G4 pierce dwell, pierce placed OFF the finished edge with a lead-in so the blowout lands in scrap. --pierce-delay and --lead-in on the CLI.
  • SVG input — path/rect/circle etc. parsed to polylines; window shows it as an amber frame sized from the SVG's width/height attrs.
  • Chat prep — describe the cut in English; the Tia-resident LLM emits one JSON command; Iris applies input/mode/dither/power/kerf to the panel (window) or runs the engine directly (CLI, with a Y/n confirm).

Using it

Control Does
Ask Iris… (chat) zenity prompt → LLM → settings applied to the panel
Load art… / drag-drop image or SVG onto the bed
Aspect: locked/FREE corner drags keep or break the ratio
Mirror ⇄ / Flip ⇅ orientation, baked into the texture and the G-code
W / H + Unit exact size; px reads the source image's own pixels
Process laser ↔︎ plasma (plasma forces outline — no engrave)
Mode engrave (raster) ↔︎ outline (vectorize); SVG is always vector
Dither / Power / Kerf cycle through the steps
GENERATE -> .nc run the engine, save, draw the cut preview

Engine-only knobs (CLI, not in the window): --feed, --border-feed, --min-power, --smax, --laser-mode M3|M4, --threshold, --brightness, --contrast, --invert, --border, --passes, --dir, --ppm, --gray, --pierce-delay, --lead-in. The chat lane can reach most of these; the window sends size/offset/power/kerf/dither/mode only.

Plasma plates: draw the plate as an SVG (closed paths), Process: plasma, kerf = your torch kerf. Pierces land off-edge automatically.

How it connects

  • Buck Dome — Iris cuts the plasma plates that Ouranos's miter-and-plate hubs call for: plate outline SVG in, pierced-and-led-in plasma G-code out.
  • Chat needs Tia — iris_chat.py probes Tia's OpenAI-compatible llama-server ports in order :18140 (gemma preferred), :18205, :18130, :18120, :18102, :18103 and uses the first warm one. Nothing warm = loud error, exit 1. The window sets IRIS_CHAT_HOST=10.0.0.2; CLI defaults to localhost (Iris is Tia-resident in deployment).
  • Styx lease — chat rides whatever resident server already holds the GPU; it never takes the lease itself. Any GPU job you run around Iris goes through flock /tmp/xos_gpu_lock.json <cmd> like everything else.
  • Labyrinth (toolpath viewer, ex-Daedalus) — can open the generated .nc for a backplot. Flat cuts don't need it: the Iris bed preview IS the backplot for 2D. Labyrinth earns its keep on mill/router work.

Known limits

  • Kerf is uniformly outward — no inner/outer contour detection. Every closed path grows by kerf/2, so HOLES COME OUT UNDERSIZED by one kerf. Until hole-aware offsetting lands: cut holes at kerf 0, or oversize them in the drawing.
  • Kerf reaches SVG mode only, and only closed paths — the engine refuses kerf on raster modes (including vectorize of a raster), and open SVG paths pass through uncompensated. A path that vanishes under the offset is skipped with a comment in the G-code.
  • Post-GENERATE preview hang — a known issue after generation floods the preview; fix is queued. If the window wedges after GENERATE, the .nc on disk is already complete and good.
  • Rust engine covers raster engrave only — vector, SVG, and plasma lanes still run the Python engine. vectorize shells out to potrace (GPL — invocation only, no GPL code linked or vendored).
  • potrace missing = silent-ish fallback — vectorize falls back to line2line with only a printed warning. Check the console if an "outline" came out shaded.
  • Bed-size mismatch — the window bed is 850×850 (Ray5 + XY kit); the Python engine's work-area preset is still 762×812.8 (30"×32"). Placement near the far edges trusts the window, not the engine preset.
  • SVG sizing is best-effort — read from width/height attrs (px assumed at 96 dpi); a header with no size defaults to 100 mm square.
  • zenity is required for every dialog (load, save, chat prompt).
